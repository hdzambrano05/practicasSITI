01
Visión general

La API gestiona un flujo completo de firma documental que combina presentación visual, procesamiento interno y validación criptográfica. El sistema contempla controladores de acceso, clases de negocio, certificados, carpetas de trabajo y librerías externas para construir, firmar y entregar documentos listos para uso institucional.

📄

Propósito principal

Automatizar la creación y firma de documentos digitales, integrando firma visible del usuario, certificado digital y almacenamiento controlado del archivo final.

⚙️

Tipo de solución

API backend en PHP con librerías especializadas para PDFs, correo, QR y manejo de recursos criptográficos, organizada por capas de acceso y clases reutilizables.

🏛️

Escenario de uso

Emisión de oficios, constancias, comunicaciones internas o documentos que requieren evidencia visual de firma y una capa de integridad digital certificada.

02
Estructura del proyecto

Organización funcional identificada en /var/www/html/ApiFirma/ — separa autenticación, certificados, lógica de negocio, configuración, librerías, almacenamiento y temporales.

/aut/
Punto de entrada del proceso. Contiene firma.php e index.php — módulo de autenticación y ejecución del flujo de firma desde interfaz web o cliente HTTP.
Acceso
/certificados/
Almacena certificado.crt y clave_privada.pem. Carpeta crítica: restringir acceso total. Material criptográfico usado para sellado digital del PDF final.
Crítico
/clases/
Lógica de negocio principal. Incluye FirmaDigital.php, FirmaRepository.php, PdfFirmado.php, QrFirma.php y cliente.php. Concentra firma, repositorio y construcción del PDF firmado.
Lógica
/docs/
Recursos visuales y resultados finales. Subcarpetas firmados/ y qrs/ almacenan el PDF sellado y los códigos QR asociados. También contiene firma.jpg.
Entrega
/include/
Configuración centralizada: Config.php, ConfigFirma.php, DbConnect.php y DbHandler.php. Parámetros de firma, rutas sensibles y posible capa de persistencia.
Config
/libs/
Dependencias externas: dompdf, FPDF, FPDI, phpmailer, phpqrcode y Slim. Soporte a generación de PDF, QR, correo y estructura HTTP de la API.
Libs
/tmp/
Archivos intermedios del pipeline: PNG de firma, HTML convertidos a PDF y versiones preliminares. Carpeta esencial en el proceso — requiere limpieza periódica para evitar acumulación de datos sensibles.
Temporal

Componentes clave

Componente Ubicación Responsabilidad Nivel

04
Flujo operativo

El proceso se desarrolla en seis etapas consecutivas — desde la recepción de la solicitud hasta la entrega del PDF sellado con firma criptográfica y QR de trazabilidad.

PASO 01
Recepción de la solicitud
El cliente envía la información del documento, los datos del firmante y la imagen de firma visible en formato PNG o ruta temporal disponible en el servidor.
PASO 02
Generación de archivos intermedios
El sistema crea recursos auxiliares dentro de /tmp/ — imágenes PNG de la firma, versiones HTML y PDFs preliminares necesarios para componer el documento final.
PASO 03
Construcción del documento visual
Mediante FPDF, FPDI o DOMPDF se compone el contenido, se insertan datos institucionales, la firma visible del usuario y elementos gráficos como el código QR de validación.
PASO 04
Aplicación de firma criptográfica
La API usa certificado.crt y clave_privada.pem para sellar digitalmente el PDF, garantizando integridad y autenticidad documental verificable por terceros.
PASO 05
Almacenamiento del resultado
El archivo firmado se publica en /docs/firmados/. Los QR generados quedan en /docs/qrs/. Los temporales en /tmp/ son candidatos a eliminación inmediata.
PASO 06
Respuesta al cliente
La API retorna estado de éxito o error, junto con la ruta o referencia del documento firmado para su descarga, distribución o consulta posterior desde otros sistemas.
05
Endpoints

Endpoints reales implementados en la API de firma digital.

POST /firma/html Firmar documento desde HTML

Genera un documento PDF a partir de contenido HTML y aplica firma digital.

  • Convierte HTML a PDF
  • Inserta firma visible
  • Genera código QR
  • Aplica firma criptográfica
REQUEST BODY 
{
  "nombre": "Harold Zambrano",
  "correo": "usuario@correo.com",
  "ciudad": "Pasto",
  "html_contenido": "<h1>Documento</h1>",
  "nombre_documento": "archivo.html",
  "foto_firma": "base64_opcional",
  "ruta_firma": "/ruta/opcional/firma.png"
}
POST /firma/pdf Firmar PDF existente

Firma un documento PDF enviado en base64 o desde una URL.

  • Soporta base64 o URL
  • Valida el archivo PDF
  • Aplica firma digital
  • Genera QR de verificación
REQUEST BODY 
{
  "nombre": "Harold",
  "correo": "correo@ejemplo.com",
  "ciudad": "Pasto",
  "pdf_base64": "opcional",
  "pdf_url": "opcional",
  "foto_firma": "base64",
  "ruta_firma": "/ruta/firma.png"
}
GET /firma/verificar/{token} Verificar documento

Permite validar la autenticidad de un documento firmado mediante su token.

  • Consulta información del documento
  • Retorna datos del firmante
  • Permite trazabilidad
GET /firma/descargar/{token} Descargar documento

Descarga el PDF firmado directamente desde el servidor.

  • Entrega archivo PDF
  • Usa token único
  • Controlado por backend
AUTH Authorization Header Token requerido

Todos los endpoints de la API requieren un token de autorización para su funcionamiento. Este token se encuentra configurado en el archivo /include/Config.php como API_KEY.

  • Debe enviarse en el header Authorization
  • Es obligatorio para todas las peticiones
  • Si no se envía → error de acceso
  • Si es inválido → acceso denegado
HEADERS 
                        Authorization: TU_API_KEY
                        Content-Type: application/json

07
Seguridad y buenas prácticas

Esta API maneja certificados digitales, rutas de archivos sensibles y documentos con validez institucional. Los controles de seguridad deben documentarse y auditarse desde el inicio del despliegue.

🔐 Protección del certificado

  • Restringir acceso directo a /certificados/ mediante reglas de servidor web
  • No exponer clave privada en repositorios ni sistemas de respaldo inseguros
  • Usar permisos mínimos necesarios a nivel de sistema operativo (chmod 400)
  • Separar rutas sensibles en archivos de configuración protegidos fuera del webroot

🗂️ Control de archivos temporales

  • Eliminar periódicamente el contenido de /tmp/ con cron job automatizado
  • Validar tipo y tamaño de archivo antes de convertir o insertar recursos
  • Evitar dejar firmas visibles o documentos preliminares de forma indefinida
  • Usar nombres únicos (UUID o hash) para prevenir colisiones entre solicitudes concurrentes

🌐 Control de acceso HTTP

  • Proteger endpoints con autenticación por token o API key
  • Validar origen de solicitudes y aplicar CORS restrictivo
  • Limitar tasa de solicitudes para prevenir abuso del proceso de firma
  • Registrar en log cada operación de firma con identificador trazable

📋 Rotación y validez del certificado

  • Documentar fecha de expiración del certificado digital y programar renovación
  • Mantener un registro de documentos firmados con cada versión del certificado
  • Definir proceso de revocación si el certificado es comprometido
  • Verificar integridad del certificado antes de cada ciclo de firma en producción
Importante: La carpeta de certificados, la carpeta temporal y la de documentos firmados deben formar parte del plan de seguridad operativa. En una documentación profesional conviene especificar permisos exactos, política de limpieza, rotación de certificados y control de acceso a los archivos emitidos con validez institucional.
08
Dependencias tecnológicas

Librerías que dan soporte al flujo documental. Documentarlas explícitamente facilita mantenimiento, instalación y soporte a largo plazo.

PDF FPDF

Generación programática de documentos PDF con control detallado sobre texto, imágenes y posicionamiento de elementos.

PDF FPDI

Importación y reutilización de páginas PDF existentes para componer o extender documentos antes del sellado final.

HTML→PDF DOMPDF

Conversión de contenido HTML a PDF, útil cuando el documento nace desde plantillas web o contenido renderizado dinámicamente.

QR phpqrcode

Generación de códigos QR para validación, trazabilidad o acceso rápido al documento o sus metadatos desde dispositivos móviles.

MAIL phpmailer

Envío de documentos firmados por correo electrónico. Soporte SMTP, adjuntos y plantillas HTML para notificaciones institucionales.

HTTP Slim

Micro-framework PHP que estructura las rutas HTTP de la API, el middleware y el manejo de solicitudes y respuestas de forma limpia.
